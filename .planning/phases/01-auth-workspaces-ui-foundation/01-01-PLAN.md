<task type="auto">
  <name>Task 2: Configure database, better-auth, and generate schema</name>
  <files>
    drizzle.config.ts
    src/lib/db/index.ts
    src/lib/db/schema/auth.ts
    src/lib/db/schema/index.ts
    src/lib/auth.ts

    src/app/api/auth/[...all]/route.ts
  </files>
  <action>
    1. Create `src/lib/db/index.ts` -- Drizzle database connection using postgres.js driver:
       ```typescript
       import { drizzle } from "drizzle-orm/postgres-js";
       import postgres from "postgres";
       import * as schema from "./schema";

       const queryClient = postgres(process.env.DATABASE_URL!);
       export const db = drizzle(queryClient, { schema });
       ```

    2. Create `drizzle.config.ts` at project root:
       ```typescript
       import { defineConfig } from "drizzle-kit";
       export default defineConfig({
         schema: "./src/lib/db/schema/index.ts",
         out: "./src/lib/db/migrations",
         dialect: "postgresql",
         dbCredentials: {
           url: process.env.DATABASE_URL!,
         },
       });
       ```

    3. Create `src/lib/auth.ts` -- better-auth server instance with organization plugin. Follow the EXACT pattern from the research doc (Pattern 1). Key config:
       - drizzleAdapter with provider "pg" and schema
       - emailAndPassword enabled
       - session: expiresIn 7 days, updateAge 1 day, cookieCache enabled (5 min)
       - organization plugin: creatorRole "owner", membershipLimit 50, invitationExpiresIn 48 hours
       - sendInvitationEmail callback: log the invitation link to console (v1 -- no email service)
       - nextCookies() plugin for server action cookie handling
       - Export Session type

    4. Create `src/lib/auth-client.ts` -- better-auth client instance (Pattern 2 from research):
       - createAuthClient with organizationClient plugin
       - Export: signIn, signUp, signOut, useSession, organization

    5. Create `src/app/api/auth/[...all]/route.ts` -- the better-auth API route handler:
       ```typescript
       import { auth } from "@/lib/auth";
       import { toNextJsHandler } from "better-auth/next-js";
       export const { GET, POST } = toNextJsHandler(auth);
       ```

    6. Generate better-auth schema for Drizzle:
       ```bash
       npx @better-auth/cli@latest generate --output src/lib/db/schema/auth.ts
       ```
       This creates the Drizzle schema definitions for all better-auth tables (user, session, account, verification, organization, member, invitation).

    7. Create `src/lib/db/schema/index.ts` barrel export:
       ```typescript
       export * from "./auth";
       ```

    8. Ensure PostgreSQL is running locally (check with `pg_isready` or attempt connection). If not available, document that user needs Docker PostgreSQL:
       ```bash
       docker run --name invoice-nest-db -e POSTGRES_PASSWORD=postgres -e POSTGRES_DB=invoice_nest -p 5432:5432 -d postgres:16
       ```

    9. Run Drizzle migrations:
       ```bash
       npx drizzle-kit generate
       npx drizzle-kit migrate
       ```
       This creates all better-auth tables in PostgreSQL.

    CRITICAL ORDER: Configure better-auth FIRST (step 3), THEN generate schema (step 6), THEN export in barrel (step 7), THEN run drizzle-kit generate and migrate (step 9). The research doc warns about this pitfall (Pitfall 2).
  </action>
  <verify>
    - `src/lib/db/index.ts` exists and exports `db`

    - `src/lib/auth-client.ts` exists and exports signIn, signUp, signOut, useSession, organization

    - `src/lib/db/schema/auth.ts` contains pgTable definitions for user, session, account, verification, organization, member, invitation
